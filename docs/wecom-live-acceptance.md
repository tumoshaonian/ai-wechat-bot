# 企业微信真实端验收清单

状态：2026-09-12 尚未执行手机端验收。自动测试使用模拟微信通道，不能替代本清单。

## 前置条件

- 保留 `.runtime/admin`、`.harness-sessions` 和真实配置备份，不删除旧会话记录。
- 后台 Agent 配置中检查已发布版本。策略发布不热更新；先结束正在执行的任务，再从启动器重启 Bridge。
- 确认日志显示机器人已认证，并在任务中心核对本次任务 `task.policy` 中的实际配置版本。仅看“已发布”不能证明进程已加载。
- 仅由允许的原请求用户参与测试。首次验收不要测试删除真实资料、付款、发给第三方或改系统设置。

## 待执行用例

1. 普通聊天与记忆：发送“你好，我这次测试的项目名是星桥”，再问“刚才的项目名是什么”。确认两条任务回复成功且答案一致；发送 end 后再问，不应以旧会话记忆回答。
2. 自然语言交付：发送“把这个机器人项目中的 README.md 文件发给我”。核对实际工具参数后确认，检查手机收到的文件能打开、内容正确且仅一份。后台上传/发送回执不代表用户已经阅读。
3. 批准操作：要求在本项目 `.harness-sessions/acceptance/` 下创建一个带唯一测试编号的文本文件。先确认文件不存在，核对提示中的路径和内容后批准；确认执行前无文件、批准后内容正确。
4. 拒绝与过期：使用另一个唯一文件名执行同类测试，回复 `/拒绝 编号`；再使用新编号测试不回复直至过期。两种情况都不应产生目标文件，旧编号不得再授权。
5. stop 和 end：等待确认时发送 stop，确认任务停止；重新发起后等待确认时发送 end，确认旧任务停止且后续消息进入新会话。不要把已经发生的操作误认为被回滚。
6. 配置生效：创建含 `bash=deny` 的新版本并发布。不要执行危险命令；重启后用安全写测试确认 bash 调用直接被策略拒绝。核对任务策略版本和 `tool.authorization`，不能只看模型解释。
7. 断网与重启：在独立安全任务中中断微信网络或重启测试 Bridge，检查任务终态、交付 unknown 和旧编号失效；确认未自动重放可能已经执行过的操作。发现 unknown 时先检查电脑状态，不盲目重试。

每个用例保存 Task ID、实际版本、手机回复、电脑上的实际结果及后台回执。遇到不一致就记录失败，不能用模型“已完成”代替证据。
