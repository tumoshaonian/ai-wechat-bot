## Harness 更新核对

- 比较范围：`0a53fb55be..d347e70390`，后者是 0.1.3-alpha.1 发布合并。
- 本次更新没有修改 Python `api.py` 和 SDK `server.ts` 的实际调用接口；仍只有初始化、提示和关闭等入口，没有新增 Python 单轮取消或冷会话恢复方法。

## 已实现

- 删除自然语言桌面文件匹配器及其快捷返回分支；普通请求完整进入 Harness；旧 `/文件` 也转为 Agent 请求。
- 添加 loopback 交付服务与 `deliver_file` MCP 工具：随机服务凭据、本轮临时票据、可信接收对象绑定、文件读取/发送权限检查、50MiB 文件上限、任务内及持久化交付去重、失败或未知回执不自动重发。
- 实际交付回执写入模型工具结果和渠道历史；文件标签仅保留兼容路径，不再自动合并中间截图。
- 新增 SQLite 渠道事实日志与逻辑会话 epoch；运行时身份加入随机命名空间，避免重启同名创建冲突。重建本版开始记录的请求、回复和交付事实；普通失败不清空已记录事实；`end` 不继承旧 epoch。
- 会话身份包含连接 ID，并同步修正后台结束会话命令及内存消息去重命名空间。
- 原生 compaction 覆盖配置显式启用，阈值 75%、近期保留比例16%。冷恢复另有字节预算，超过时尝试有界摘要加近期完整轮次；摘要不合格或达到上限则明确报错。
- 渠道摘要保存不可变检查点与覆盖序号，不删除原始事实；按 epoch 和前一检查点做事务校验，避免 `end` 后旧摘要污染新会话。晚到回执继续追加，不被旧检查点吞掉。
- 摘要使用临时隔离的 Harness Profile，关闭桌面工具、禁止全部工具执行。最多 8 批，至少保留最新完整轮次。停止／结束会话覆盖恢复阶段，重复取消不遗留摘要进程清理任务。恢复成功及失败元数据进入现有任务事件，不写完整历史正文。
- `prepare_window` 识别无所有者的主窗口候选，排除小辅助窗口；验证 HWND/PID 后恢复最小化或屏幕外窗口，再确认可见和可交互。候选不唯一时拒绝猜测。
- 豆包问答接入窗口准备；控件缺失不再自动杀进程重启。
- 整轮错误解释和 Runtime teardown 纳入同一串行边界，避免旧任务失败关闭后续任务；取消返回后不继续交付已中断结果。
- 显示实际工具阶段；未解决工具错误或输出上限不标为完全成功；上传未确认时明确部分完成。
- 阶段 5 的结果追踪子阶段：Agent 返回结果后先记录 `agent.execution.completed`，再尝试文件提示和最终回复。回复异常保留执行结果，任务标记部分完成，回复回执为 unknown，不把它解释成电脑执行失败，也不自动重放任务。
- 后台任务投影增加单向状态约束：终态不再被晚到的进度、开始或冲突终态覆盖；原始事件仍保留审计。取消请求在确认结果前保持“正在停止”。未知 task 事件不制造运行中任务。
- 同一会话等待处理锁时记录 QUEUED，取得锁后记录 RUNNING；耗时从开始处理到终态计算，不包含同会话排队时间。它不代表跨会话桌面资源已独占，也尚不包含完整持久队列。
- 后台任务详情独立展示 Agent 执行结果、最终回复回执及文件交付。文件发送异常记录 UNKNOWN；出站回复异常不再错误投影成 SENT。此能力不把模型声称完成当成工具效果已验证，仍需查看工具证据。
- 消息处理层现在拥有任务句柄，后台取消命令接入处理层而不是仅找 Harness。支持精确取消当前进程中尚未进入 Harness 的排队任务，不误停其他任务；完成清理后才记录取消成功。
- 微信 stop 停止当前会话活动及排队任务；end 排空旧任务后再建立新会话边界。结束期间新请求明确拒绝，避免混入旧记忆或在新会话执行旧排队请求。关闭处理器同样排空已有任务；已发生的操作不回滚。
- 默认提示词移除软件名绑定的提问规则，补充应用无关的工具选择与通用生成／导出约束。现有专用工具保留为可选适配，没有因此新增或虚报视觉能力。
- 确认交互阶段：新增 `request_confirmation` MCP 工具，描述操作、目标和影响；随机一次性编号绑定连接／会话、原请求用户、任务及 epoch，记录描述摘要和决定。微信 `/确认 编号`、`/拒绝 编号` 走独立控制入口，不排在等待中的任务后面。
- 等待确认默认最多90秒，发送提示最多10秒且计入总确认预算；普通“确认”不授权。过期、拒绝或确认交互故障会停止当前所属 Runtime；stop、end、任务超时同样撤销等待。重启后的旧编号不能恢复或自动执行，原始记录保留。
- 确认期间后台显示 WAITING_CONFIRMATION，普通进度不覆盖等待状态；确认结果写入渠道事实日志，明确它不代表操作已经完成。确认本身仅批准展示的操作意图，不是所有通用工具的强制参数级授权控制。

## 尚未完成／不能算通过

1. **原生完整冷恢复**：渠道摘要恢复已经实现并通过真实测试，但属于有损压缩，不含完整工具轨迹，也不保证记住所有细节。已启用的 Harness 原生 compaction 只处理活跃会话，尚未做强制原生长上下文压缩验证。超大单轮及超限积压仍安全拒绝。
2. **旧版历史迁移**：连接命名空间已修正，旧日志、旧注册表和后台对话记录保留，但旧版内容不会自动导入新渠道日志。首次升级可视为明确的记忆起点。
3. **所有工具的执行级权限**：文件交付执行器有强制校验，确认工具完成一次性交互并在拒绝／过期时停止任务。但是否在高风险动作前发起确认仍依赖 Agent，确认描述也尚未绑定到所有真实工具参数；不能将此视为 shell/通用桌面全覆盖的安全隔离，需进一步接入 Harness 执行策略。尚不建议向不可信多人开放完整电脑控制。
4. **持久任务恢复与完整状态机**：当前进程的精确排队取消、end 清空旧队列、终态保护、执行与回复分离及有时限的确认交互已补齐。持久排队及排队时限、跨进程续跑、多任务资源仲裁、微信通道恢复仍未完整实现；确认等待不会跨重启自动恢复。取消其他 Bridge 实例的任务仍拒绝。终态冲突仅保留审计，不自动纠正或重试；已有错误历史也不会自动重算。
5. **真实企业微信收件验收**：交付服务的真实模型路径和测试接收器通过，实际企业微信收件及断网回执尚未测试。
6. **通用应用成果生成／导出**：目标是由 Harness 在用户指定的任意目标应用中规划生成、编辑、导出、验证及发送，不为豆包写死专属流程。当前没有完成跨应用保存／导出能力验收；豆包只保留为样例。移除错误文件匹配不等于通用导出已经实现。
7. **通用受控视觉操作**：目标是应用无关的“观察→定位→动作→验证”闭环；专用适配仅是可选增强。不要求提前注册每个软件，但也不承诺任意界面必定成功。视觉模型、截图隐私范围及调用成本仍需确认；尚未引入视觉执行能力或开放全局键鼠脚本。B站等应用仅作回归样例，不能以浏览器搜索替代客户端验收。
8. **管理后台配置界面**：任务详情已有执行／回复分离、文件交付未知和等待确认状态展示；确认／拒绝当前只通过原用户微信命令，没有后台代确认按钮。上下文用量、恢复方式专门展示及可编辑策略页面尚未完整补齐。
