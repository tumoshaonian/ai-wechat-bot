# 从 Java 后端到 AI Agent 开发：学习计划

适用对象：有 Java 后端基础，能借助 AI 完成前后端项目，希望用 Python 学习 Agent，并以当前企业微信机器人参加初级岗位面试。

编写与资料核对日期：2026-09-11。时间为学习安排估算，不是岗位录用承诺。框架和模型接口会变化，安装时以官方文档及锁定版本为准。

配套教材：[02-Agent开发知识手册](D:/a-TuMo/study/project/ai-wechat-bot/docs/learning/02-Agent开发知识手册.md)。本计划负责说明顺序、练习、产出与验收；手册负责直接讲解知识和示例。

## 1. 最终要达到什么水平

完成后，目标是能够解释并演示以下内容：

- 从 Token、注意力和 Transformer 讲到预训练、SFT、RLHF，能区分训练与推理。
- 用 Python 调用一种模型服务，读懂另外两种服务的工具调用协议。
- 解释 Agent 如何选择工具、接收结果、继续执行和停止。
- 实现一个小型 RAG，理解检索、重排、引用和评测，而不只是连接向量库。
- 使用一套 Agent 框架完成有状态流程，理解多 Agent 的分工与代价。
- 解释当前微信机器人的 SDK、MCP、会话恢复、取消、确认和交付回执。
- 用真实任务集证明系统效果，知道什么失败了以及怎样改进。
- 在面试中区分“项目已实现”“实验已验证”“仅了解原理”。

本路线面向 Agent 应用开发。分布式预训练、CUDA 内核优化、大规模 RL 训练和论文复现不属于首次求职准备的必修项。

## 2. 时间与学习方式

### 2.1 推荐节奏：约 100 小时

十个阶段的基准用时依次为 **4、12、8、10、16、10、8、12、8、12 小时，总计 100 小时**。根据 Python 熟练度和排错时间，实际可能更长。

- 每周 15～20 小时：约 5～7 周。
- 每天 4～6 小时：约 17～25 个学习日，另留休息与排错余量。
- 一周 40～50 小时：适合完成第一轮认知和部分练习，不能默认等同于完整路线。

### 2.2 按你的偏好：理论先行，再回到项目

采用两遍学习，不要求你边读每一个概念边改现有系统。

**第一遍，约 35 小时：**顺序阅读知识手册第 1～12 章，再读第 14 章。每章先完成口头自测和纸面练习；保留代码实验到第二遍。你要先建立整个系统的理解。

**第二遍，约 65 小时：**回到本计划各阶段，完成代码练习、项目映射和面试演练。两遍合计约 100 小时，并非额外叠加两套时间。

每个学习单元采用“阅读 → 不看资料复述 → 一个例子 → 自测 → 记录疑问”。能复述概念但不会举例，或能运行代码但解释不了，都算尚未通过。

### 2.3 掌握深度

- **必修：**能解释原理、完成小练习、回答追问。
- **实作：**有可运行代码、输入输出、失败案例和记录。
- **选修：**知道解决什么问题，首次面试不要求完整实现。

除主修框架外，其余框架先达到“能说明定位与取舍”即可。不要把学习进度变成安装包数量。

## 3. 阶段 0：Python 与工程准备｜4 小时

**对应教材：第 1 章。前置：已有后端基础。**

学习内容：类型提示、list/dict、函数与类、dataclass、异常、上下文管理器、模块、虚拟环境、JSON、环境变量、async/await、超时与取消。

重点迁移：Java 接口到 Python Protocol；DTO 到 dataclass/Pydantic；线程池到 asyncio 与阻塞任务隔离；Maven 依赖到 pyproject 和锁文件。

练习：运行手册中的无网络 Python 示例；写一个接收 JSON 请求、校验字段并返回结果的函数；并发执行两个模拟 I/O 任务，观察串行和并发耗时。

产出：个人术语笔记，以及一个独立练习目录。学习环境与微信机器人现有环境分开，避免升级框架影响正在工作的项目。

验收：能解释为什么在 async 函数里直接调用阻塞 SDK 仍可能卡住事件循环，为什么协程取消不代表远端操作已撤销。

## 4. 阶段 1：LLM 基础与训练流程｜12 小时

**对应教材：第 2、3 章。前置：阶段 0。**

学习内容：Token、向量与点积、softmax、Embedding、自回归、Q/K/V、因果掩码、多头注意力、位置编码、前馈层、残差与归一化、Encoder/Decoder、上下文窗口、KV Cache；预训练、SFT、RLHF、PPO、DPO、LoRA、量化基础。

练习：手算一次两个位置的注意力权重；分别写一条 SFT 样本和一条偏好样本；针对“知识过期、输出格式错误、工具失败”判断应该优先改哪里。

产出：一张自己画的生成流程图；一段三分钟讲解；一页“Prompt、RAG、微调的选择依据”。

验收：不看资料解释注意力公式各项作用；说明多头不是多 Agent；说明低温度不等于不会幻觉；说明 SFT/RLHF 与应用中追加聊天记录不同。

暂不要求：完整推导反向传播、从头训练 Transformer、租 GPU 做大模型训练。

## 5. 阶段 2：模型 API 与提示词｜8 小时

**对应教材：第 4 章。前置：阶段 1。**

学习内容：消息角色、无状态请求与会话管理、流式输出、结构化输出、工具调用、finish reason、超时、重试、限流、模型参数、用量记录；任务描述、约束、示例、输出协议与不可信输入边界。

练习：选当前能够合法访问、有凭据的一家模型服务，完成纯文本、结构化提取、一次工具调用。阅读另两家官方协议，记录差别，不要求购买三家服务。

产出：三个请求/响应样例和一个错误记录。隐藏密钥、身份信息及私有文件内容。

验收：模型返回工具调用后，由谁执行函数？JSON 合法是否代表字段或业务含义正确？请求超时能不能直接重做有副作用的操作？

主修建议：优先复用你已经使用的模型服务；了解 OpenAI、Claude、智谱的接口形态，不为了面试强行切换机器人主模型。

## 6. 阶段 3：单 Agent、工具与 MCP｜10 小时

**对应教材：第 5、6 章。前置：阶段 2。**

学习内容：Agent 与工作流、ReAct、计划与执行、工具 Schema、观察结果、终止条件、预算、人工确认；MCP 的 Host/Client/Server、工具发现、调用和传输。

练习：先运行手册中不联网的工具循环示例，再接入真实模型；只开放一个只读查询工具；测试未知工具、错误参数、工具失败、达到最大步数四种情况。

产出：一份真实工具调用轨迹，包含请求、工具名、参数、结果与最终输出；一页“MCP 与 Function Calling 的关系”。

验收：能指出模型决策、应用执行、协议适配各在哪里；能解释现有项目为什么算 Agent，以及核心循环为什么主要属于 Harness SDK。

## 7. 阶段 4：RAG 从原理到可验证原型｜16 小时

**对应教材：第 7 章、第 11 章中的 RAG 评测。前置：阶段 2，建议完成阶段 3。**

学习内容：离线建库与在线检索、解析、切分、元数据、Embedding、余弦相似度、BM25、混合检索、向量索引、Top-k、重排、上下文组装、引用、拒答、增量更新、权限过滤。

练习顺序：

1. 用手册的纯 Python 示例理解“取出证据再构造请求”；知道它是教学检索器，不是向量检索效果证明。
2. 选择 10～20 份公开或自写文档，用真实 Embedding 构建一个小索引。
3. 实现查询、返回原文与来源，再让模型依据来源回答。
4. 制作 20 个开发问题和 10 个暂不用于调参的留出问题，包括无答案、同义问法、编号、版本冲突和无权限文档。
5. 比较两种切分大小或加入重排前后的结果，记录证据和失败样本。

产出：一个独立 RAG 原型、30 条问题与证据标注、一次对比实验。这里的数量是学习规模建议，不能冒充可靠的大规模业务评测。

验收：能沿着“没检索到 → 排名太低 → 上下文丢失 → 模型未遵循证据”定位问题；知道相似度不是置信概率；能解释为什么增加 Top-k 有时使答案变差。

工具选择：编排沿用 LangChain；需要进一步研究文档接入时读 LlamaIndex。小样本可用内存精确检索；数据库只选一种，不同时部署多套。

## 8. 阶段 5：记忆、状态与主修框架｜10 小时

**对应教材：第 8、9 章。前置：阶段 3。**

学习内容：短期/长期记忆、事实与摘要、上下文选择、检查点、会话 ID 与任务 ID、工具消息配对；LangChain 的模型/工具/Agent，LangGraph 的 State、Node、Edge、条件路由、持久化和中断。

练习：运行手册的无模型 LangGraph 示例；把阶段 3 的最小循环用框架重写；加入一处需要人工确认的状态转换，观察暂停与拒绝路径。

产出：同一任务的手写循环版与框架版，以及一段取舍说明。先在练习目录实现，不要求迁移整个微信机器人。

验收：能说明框架替你管理了什么；检查点为什么不等于数据库事务；为什么摘要不能作为“文件已经送达”的唯一凭证。

## 9. 阶段 6：多 Agent 与框架全景｜8 小时

**对应教材：第 9、10 章。前置：阶段 5。**

学习内容：主管分派、交接、并行、评审与返工、共享状态、任务契约、证据传递、冲突解决、步数与费用预算。

主修实践：用已经学过的框架实现“资料整理者 → 成果检查者”；输入限定为阶段 4 的测试资料，检查者必须看原文/成果，而非只看执行者自我总结。

横向理解：CrewAI 的 Agent/Task/Crew/Flow；AutoGen 的 AgentChat 与消息协作；Microsoft Agent Framework；MetaGPT 的角色与 SOP；LlamaIndex、OpenAI Agents SDK、Haystack、Dify、DSPy 的定位。

截至核对日，[AutoGen 官方仓库](https://github.com/microsoft/autogen)标注维护模式并指向 Microsoft Agent Framework。理解招聘词汇时保留 AutoGen；新学习实验不必围绕旧接口展开。

产出：一个双 Agent 实验，与单 Agent 在相同任务上的质量、调用次数和耗时对比。没有提升也是有效结论。

验收：多个 Python 进程为什么不自动等于多 Agent？什么时候并行会引发桌面冲突？为什么“互相讨论”不保证正确？

## 10. 阶段 7：评测、可靠性与 AI 辅助开发｜12 小时

**对应教材：第 11、12、14 章。前置：阶段 4～6。**

学习内容：任务集、运行环境、轨迹、判分器、结果与过程指标、重复试验、留出集、LLM-as-judge 的偏差；日志和 tracing、幂等、重试、状态恢复、权限、提示注入、超时与取消、费用控制。

理解评测工具定位：AgentBench 是 Agent 基准及环境；lm-evaluation-harness 主要用于语言模型评测；LangSmith 支持轨迹与实验；Ragas 提供 RAG 等评测能力。它们不能互相直接替代。

练习：建立最小评测脚本；对相同任务运行多次；加入不存在文件、工具超时、取消、重复交付、错误证据、提示注入等用例。桌面实验在隔离的测试目录和可控应用状态下进行。

产出：任务集、原始轨迹、判分规则、失败分类和一次改进前后对照。区分软件回归测试和模型效果评测。

验收：模型回答“完成了”为什么不能当成功判据？成功率分母是什么？怎样区分基础设施故障和模型能力失败？修改提示词后如何发现回归？

## 11. 阶段 8：映射到微信机器人｜8 小时

**对应教材：第 13 章。前置：阶段 7。**

这一步先阅读、解释和演示现有系统，再决定改造范围。

阅读顺序：统一入口 → Harness 适配层 → Desktop MCP → 会话与历史 → 应用任务编排 → 测试。手册提供具体文件链接。

产出：

- 当前系统架构与一次真实请求轨迹。
- SDK 提供能力与项目实现能力的边界说明。
- 一个成功案例和两个有证据的失败案例。
- 当前能力、实验能力、未来计划三份独立清单。

建议的后续改造：先把 RAG 做成只读的知识检索工具，复用现有 Harness 与 MCP；通过测试后再接入微信。多 Agent 可以保留为独立实验，不为凑关键词重写稳定主链路。

验收：能讲清“用户请求 → 模型决策 → 工具执行 → 结果判定 → 微信交付”的每个边界，且知道 RAG、完整多 Agent、执行级权限隔离哪些尚未实现。

## 12. 阶段 9：面试表达与补漏｜12 小时

**对应教材：第 15 章，附录术语与资料索引。前置：阶段 8。**

安排四轮：

1. 三小时：闭卷回答手册面试题；不会的问题标记回对应章节。
2. 三小时：准备 90 秒介绍与 5 分钟项目讲解，录音检查是否泛泛而谈。
3. 三小时：现场改一个工具参数或增加一种错误处理，运行验证并讲清影响。
4. 三小时：模拟追问、复习薄弱部分、整理简历和演示材料。

演示包：启动说明、脱敏配置示例、架构图、测试任务、执行日志/成果、评测报告、已知限制。真实链路不稳定时使用事先录制并说明日期的演示，不能把模拟工具结果冒充实际运行。

验收标准：手册面试题多数能用“定义 → 项目例子 → 局限/取舍”回答；关键问题即使换一种问法也能解释；能明确说出自己尚未实现的部分。

## 13. 如果你只有一周

每天按约 6 小时安排，共 42 小时；是压缩学习方案，不替代完整实作。

- **第 1 天：**第 1～2 章，Python 迁移与 Transformer；完成注意力手算。
- **第 2 天：**第 3～4 章，训练路线、API、提示词；完成一次真实请求。
- **第 3 天：**第 5～6 章，Agent、工具调用、MCP；运行模拟循环并读项目适配代码。
- **第 4 天：**第 7 章，RAG 全链路；完成教学检索示例，画出真实 RAG 方案。
- **第 5 天：**第 8～10 章，记忆、框架、多 Agent；跑无模型图示例。
- **第 6 天：**第 11～14 章，评测与项目映射；整理现有实现和缺口，设计十条评测用例。
- **第 7 天：**第 15 章；演示已有机器人，练习回答，修正简历表述。

这一周结束时可以说“了解 RAG 与多 Agent，并做过小练习”；只有真实完成实现与验证后，才说“在项目中落地了 RAG/多 Agent”。

## 14. 学习时如何使用 AI

建议向 AI 发出这样的请求：“先让我解释这段代码，再指出错误；只给提示，不直接替我完成核心循环。”

你可以让 AI 查官方接口、搭脚手架、解释错误、设计边界用例、模拟面试。每完成一个模块，合上生成过程，独立画流程并改一个需求。AI 生成的指标、跑通声明和引用必须用实际结果核对。

每次学习记录四件事：今天学会什么、一个具体例子、一个仍不明白的问题、一份实际产出。第二天先闭卷复述昨天内容。
