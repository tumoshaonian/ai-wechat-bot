# 微信电脑 Agent 后台管理系统需求规格说明书

> 文档版本：V1.0（需求基线草案）  
> 编写日期：2026-08-30  
> 适用项目：`ai-wechat-bot`  
> 建设方式：本机优先、可扩展到多机器人和多电脑节点

## 1. 文档目的

本文档定义微信电脑 Agent 后台管理系统的业务边界、用户角色、功能模块、数据模型、关键流程、权限、安全、部署方式和验收标准，作为后续原型设计、技术设计、数据库设计、接口设计、开发测试和验收的统一依据。

本文中的“微信”在第一阶段特指当前已经接入的企业微信智能机器人长连接。系统在数据模型中预留通道类型，但第一阶段不承诺接入没有稳定官方机器人 SDK 的个人微信。

## 2. 建设背景与现状

### 2.1 当前主链路

当前有效链路为：

```text
企业微信智能机器人
  -> WebSocket 长连接
  -> Python Bridge
  -> Unified Agent
  -> DeepSeek Harness
  -> 文件、命令行、Desktop MCP / Windows UI Automation
  -> 企业微信回复、进度消息和文件发送
```

Spring Boot 聊天接口和旧 OCR 微信桥接仍保留在仓库中，但已经不是统一 Agent 的主消息链路。

### 2.2 当前已有能力

- 使用企业微信 Bot ID 与 Secret 建立长连接并收发消息。
- 按 UserID 控制允许使用机器人的用户。
- 普通聊天和电脑操作统一进入 Agent，由 Agent 判断是否调用工具。
- 支持连续会话、结束会话、停止任务、查看会话状态。
- 支持执行 Harness 工具、桌面 UI Automation、截图和本地文件发送。
- 支持任务超时、进度更新、失败会话隔离和部分错误翻译。
- 桌面快捷方式可以启动或停止 Python Bridge、可选旧 Java 服务，并查看文本日志。
- Harness 会话日志、Bridge 会话代数和运行日志已经在本机文件中保存一部分信息。

### 2.3 当前缺口

- `.env` 只能表达一套当前生效的企业微信配置，不能安全管理、验证和切换多套机器人连接。
- 对话、任务、工具调用、文件发送和管理员操作之间没有统一的持久化关联。
- 当前日志主要是文本文件，无法按用户、会话、任务、工具和错误类型检索。
- 只能看到“程序输出了什么”，不能快速回答“用户提出了什么、Agent 实际做了什么、在哪一步失败、产生了哪些文件”。
- PowerShell WinForms 窗口适合作为本机启动与故障排查工具，不适合作为完整业务管理后台。
- 配置变更缺少版本、发布、回滚、审计和敏感字段保护。
- 没有后台账号、角色权限、审批策略、告警、数据保留和备份恢复机制。

### 2.4 当前实现约束

- 当前消息去重只保存在进程内最近 2,000 条 message ID 中，Bridge 重启后不能阻止同一平台消息被再次执行。
- 当前 `DeepSeekHarnessBackend` 使用一个全局执行锁和单线程执行器，不同微信会话的 Agent 任务实际上也会全局串行。
- Harness Python SDK 已提供 `run(..., on_notification=...)` 通知回调，但当前适配器尚未接入；该回调应作为实时任务时间线的首选事实来源，避免轮询或反复解析压缩会话日志。
- Harness 压缩会话日志是底层追加式档案；后台应通过正式接口读取，不应直接编辑或把所有流式字符块逐条索引到关系数据库。
- 旧会话注册表只保存 chat ID 的不可逆哈希，不能完整反查企业微信用户；后台启用后必须从消息入口开始建立正式映射。
- 企业微信文件发送当前会一次性将文件读入内存，接近 50 MiB 上限时需要关注内存峰值，后续应采用受 SDK 支持的流式或分块方案。
- Desktop MCP/UIA 必须运行在已登录用户的交互式桌面会话中，不能简单搬到 Windows Session 0 服务中运行。

## 3. 系统定位与建设结论

后台管理系统是微信电脑 Agent 的“控制面与审计面”，不直接取代执行 Agent。它负责配置、授权、观察、控制、追溯和运营；Python Bridge、Harness 和 Desktop Worker 继续负责实时消息处理和电脑操作。

桌面快捷启动器应保留并演进，但不应继续把完整后台页面堆进现有 PowerShell 窗口。推荐形成以下两个层次：

1. **本机节点控制器（Local Supervisor）**：负责启动、停止、重启和健康检查 Bridge、Harness 子进程、Desktop Worker、后台 API；提供受限的本机控制接口；即使后台 API 异常也能完成故障恢复。
2. **Web 管理后台（Admin Control Plane）**：负责对话、任务、工具、文件、微信连接、用户权限、配置、实时日志和审计管理，通过浏览器使用。

桌面快捷方式最终应变成统一入口：启动本机节点控制器和后台服务，随后打开浏览器管理页。原有日志窗口可作为“高级诊断/应急控制台”保留，而不是日常主界面。

## 4. 建设目标

### 4.1 主要用途

- 集中查看用户与机器人的完整对话记录。
- 追踪每个用户请求对应的 Agent 任务、结构化步骤、工具调用、电脑操作和最终结果。
- 管理多个企业微信机器人连接，支持验证、启停、切换和故障回滚。
- 管理允许使用机器人的用户、操作权限和高风险操作审批策略。
- 管理 Agent 模型、提示词、工具权限、超时、文件发送等配置，并支持版本和回滚。
- 查看服务状态、实时日志、错误告警和电脑节点能力。
- 在必要时停止任务、结束会话、重试失败任务或重新发送文件。
- 为事故排查、安全审计和后续功能优化提供可信数据。

### 4.2 成功标准

- 任意一条微信消息都能关联到发送用户、微信连接、会话、Agent 会话代数和任务。
- 任意一次电脑操作都能看到调用工具、输入摘要、开始与结束时间、执行结果、错误和证据文件。
- 从任务失败页面可以直接定位失败阶段和相关日志，而不需要手工翻阅多个日志文件。
- 切换微信机器人时不会覆盖旧配置；新连接认证失败时能自动回滚到原连接。
- 敏感凭据不以明文出现在页面、数据库查询结果、日志或导出文件中。
- 后台或 Bridge 重启后，历史记录仍可查询，未完成任务能被标记为异常中断而不是永久“处理中”。

## 5. 系统范围

### 5.1 第一阶段范围

- 单台 Windows 电脑节点。
- 企业微信智能机器人长连接。
- 一个后台超级管理员，可扩展为多管理员 RBAC。
- 多套企业微信机器人配置，默认同一时刻一套主连接生效。
- 对话、消息、任务、任务步骤、工具调用、文件、发送记录、配置和审计日志持久化。
- 本机服务启停、状态检查、实时日志和错误告警。
- Agent 配置和授权策略管理。

### 5.2 后续扩展范围

- 多个机器人同时在线，并将不同机器人、用户或任务路由到不同电脑节点。
- 多台 Windows 电脑节点与远程节点升级。
- 企业级统一身份认证、双因素认证、审批流和告警渠道。
- 统计报表、成本分析、模型效果评估和任务质量标注。

### 5.3 明确不在第一阶段范围

- 个人微信非官方协议、Hook、注入或绕过平台限制的接入。
- 绕过 Windows 锁屏、UAC 安全桌面、验证码和系统安全边界。
- 记录或展示模型私有思维链。后台只保存可审计的任务计划摘要、工具调用和结果。
- 完整的远程桌面视频控制产品。
- 同一桌面上用户与 Agent 同时抢占焦点的冲突治理。

## 6. 用户角色与权限

### 6.1 超级管理员

- 拥有全部后台功能。
- 创建管理员、分配角色和权限。
- 管理企业微信连接、模型凭据、系统安全策略和数据保留策略。
- 查看和导出全部审计记录。

### 6.2 运维管理员

- 查看仪表盘、服务、节点、任务、工具调用和实时日志。
- 启动、停止、重启受管服务；停止或重试任务。
- 处理告警和文件发送失败。
- 无权查看或修改完整 Secret、API Key 和最高权限策略。

### 6.3 机器人管理员

- 管理微信连接的非敏感信息、允许用户、欢迎语和路由策略。
- 查看分配范围内的对话与任务。
- 无权执行系统级进程控制和修改底层工具配置。

### 6.4 审计员

- 只读查看对话、用户操作、机器人操作、配置发布记录和管理员审计日志。
- 可按授权导出脱敏审计数据。
- 无权发起、停止或重试任务。

### 6.5 只读观察员

- 只读查看仪表盘、健康状态和脱敏日志。
- 不可查看敏感对话正文、文件内容和工具输入详情。

### 6.6 微信终端用户

- 不登录管理后台。
- 通过企业微信发送消息、文件和控制命令。
- 权限由微信身份、所属机器人、用户策略和动作风险级别共同决定。

## 7. 核心业务对象

- **微信连接**：一套企业微信机器人 Bot ID、加密 Secret、启用状态和连接策略。
- **微信用户**：企业微信 UserID 及其显示信息、授权状态和权限策略。
- **会话**：用户与某个机器人持续交流的逻辑会话。
- **Agent 会话**：Harness 持有上下文的具体代次；执行 `end`、异常隔离或配置切换时产生新代次。
- **消息**：用户输入、机器人进度、机器人最终回复、系统提示或文件消息。
- **任务**：由一条用户消息触发、需要 Agent 处理的一次工作单元。
- **任务步骤**：可公开审计的计划摘要和执行阶段，不包含模型私有思维链。
- **工具调用**：Agent 调用命令、文件、Desktop MCP 等工具的一次结构化记录。
- **电脑节点**：运行 Bridge、Harness 和桌面工具的 Windows 主机。
- **文件产物**：被读取、生成、压缩、截图或发送的本地文件元数据。
- **审批单**：高风险动作等待用户或管理员确认的记录。
- **配置版本**：微信、Agent、工具、超时和安全策略的一次可发布快照。
- **审计事件**：管理员或系统对配置、权限、连接、任务和数据执行的重要操作。

## 8. 功能需求

### 8.1 后台登录与账号安全

1. 支持后台账号密码登录、退出、登录过期和主动踢出会话。
2. 首次启动必须引导创建超级管理员，不提供固定默认密码。
3. 密码必须使用安全密码哈希保存；页面不得回显原密码。
4. 支持登录失败次数限制、临时锁定和登录审计。
5. 后续支持双因素认证和企业统一身份认证。
6. 管理接口默认只监听本机地址；若开启局域网或公网访问，必须明确提示 HTTPS、访问控制和额外风险。
7. 所有修改类请求必须校验权限并防止跨站请求伪造。

### 8.2 总览仪表盘

1. 展示当前主微信连接、认证状态、最近心跳、断线次数和重连状态。
2. 展示本机节点、Bridge、Harness、Desktop Worker、后台 API 和可选旧 Java 服务状态。
3. 展示今日消息数、任务数、成功数、部分成功数、失败数、超时数、取消数和平均耗时。
4. 展示当前运行任务、等待确认任务、最近失败任务和最近告警。
5. 展示文件发送成功数、失败数和总大小。
6. 支持从异常卡片直接跳转到对应任务、连接、服务或日志筛选结果。
7. 指标必须标注时间范围和最后刷新时间，不得把历史累计值误当成实时值。

### 8.3 企业微信连接管理

#### 8.3.1 连接配置

1. 可新增、复制、编辑、停用和删除连接配置。
2. 每个连接至少包含：名称、通道类型、Bot ID、加密 Secret、状态、所属环境、备注、创建人与更新时间。
3. Secret 只能在录入或轮换时提交；列表和详情只显示掩码，后台接口不得返回明文。
4. Bot ID 应保持唯一；删除前必须检查是否仍有关联历史和运行任务，默认使用软删除。
5. 可配置允许用户策略、欢迎语、Agent 配置版本、任务超时、文件限制和默认电脑节点。

#### 8.3.2 连接测试

1. 保存前可执行认证测试，不影响当前在线连接。
2. 测试结果应包含 DNS/网络、认证、SDK 初始化和基础连接阶段，错误信息需脱敏。
3. 测试成功不代表立即启用，必须由管理员执行“发布/切换”。

#### 8.3.3 切换策略

1. 第一阶段允许保存多套配置，但同一主执行槽默认只启用一套主连接。
2. 切换前进行配置校验和独立连接测试。
3. 若有运行任务，管理员可选择等待完成或停止任务后切换；系统不得在任务中途静默更换会话归属。
4. 切换采用“新连接先认证、旧连接后下线”的方式；新连接失败必须保持旧连接在线。
5. 切换成功后记录操作者、原连接、新连接、发布时间和结果。
6. 旧连接的历史会话仍可查询，不得因切换被覆盖或混入新连接。
7. 后续版本可允许多个连接同时在线，每个连接由独立 Worker 隔离，避免一个连接崩溃拖垮全部机器人。

### 8.4 微信用户与访问策略

1. 自动登记首次出现的企业微信 UserID、所属连接、首次/最近消息时间和消息数量。
2. 支持允许、禁用、观察和待审批状态。
3. 支持给用户设置显示名称、备注、标签和权限策略。
4. 支持按用户控制：是否可聊天、是否可调用电脑工具、是否可读取文件、是否可发送文件、是否可执行命令、最高风险级别和允许目录。
5. 拒绝未授权消息时也要保存安全事件，但默认不保存不必要的敏感正文。
6. 权限变更必须实时或在可接受的短时间内生效，并留下审计记录。

### 8.5 对话与消息记录

1. 按微信连接、用户、会话、Agent 会话代数、时间、关键词和消息状态检索。
2. 会话列表展示最后消息、当前任务状态、当前 Agent 代数、消息数和最近活跃时间。
3. 会话详情按时间线展示用户消息、进度消息、最终回复、文件消息、系统事件和控制命令。
4. 每条消息保存通道消息 ID，用于幂等去重和失败追踪。
5. 标记消息方向、类型、发送状态、错误码、响应耗时和关联任务。
6. 支持正文脱敏、按权限显示和审计导出。
7. 支持管理员执行“结束会话”，保留旧代次记录并创建新 Agent 会话代次。
8. 支持管理员执行“停止当前任务”，但停止任务与结束会话是两个独立动作。
9. 不允许从后台修改已经发送的历史消息；备注和标签应与原始消息分离保存。

### 8.6 Agent 会话管理

1. 展示逻辑会话与 Harness 具体 session ID 的映射，但普通角色只显示脱敏标识。
2. 展示会话代数、创建原因、开始时间、结束时间、当前状态、Runtime 标识和关联配置版本。
3. 创建新代次的原因至少包括：用户执行 `end`、管理员结束、任务停止、运行时异常隔离、会话碰撞恢复、机器人连接切换和配置发布。
4. 支持查看上一代次，但新代次不得继承上一代次上下文。
5. Bridge 重启后，未正常结束的运行中代次应被标记为“异常中断”，下一次请求使用新代次。
6. 不允许管理员手工编辑 Harness 历史日志；可执行归档和按保留策略清理。

### 8.7 Agent 任务管理

1. 每条需要处理的用户消息创建一个任务，并生成全局唯一 task ID 和 trace ID。
2. 任务状态至少包括：已接收、排队中、运行中、等待确认、成功、部分成功、失败、已取消、已超时、异常中断。
3. 任务详情展示请求摘要、原始消息、用户、连接、会话、配置版本、开始/结束时间、耗时、状态和结果摘要。
4. 展示结构化执行时间线：消息接收、Agent 开始、步骤、工具调用、进度回复、文件交付和最终回复。
5. 支持停止运行任务。停止请求需要记录发起者、时间、结果，并确保 Runtime 和子工具被终止或标记未终止。
6. 支持重试失败任务，默认创建新任务和新 Agent 会话代次，不覆盖原失败任务。
7. 可选择“带原上下文重试”或“全新会话重试”，高风险动作默认禁止自动重试。
8. 支持对成功、失败和部分成功任务添加人工备注与质量标记。
9. 页面应明确区分 Agent 文本回答成功与电脑实际操作成功，不能只根据最终回复判定。

### 8.8 用户操作记录

用户操作记录包括但不限于：

- 通过微信发送文本、文件和控制命令。
- 在微信中确认或拒绝高风险操作。
- 管理员在后台停止、重试、结束会话、重新发送文件。
- 管理员新增、修改、发布、切换和回滚配置。
- 管理员登录、导出、删除、归档和查看敏感数据。

每条记录至少包含操作者类型、操作者标识、操作类型、目标对象、时间、来源 IP/通道、结果、失败原因和 trace ID。敏感参数只能保存脱敏摘要。

### 8.9 机器人操作与工具调用记录

1. 保存 Agent 对任务的公开计划摘要和阶段，不保存私有思维链。
2. 每次工具调用保存工具名称、工具分类、开始与结束时间、输入摘要、输出摘要、状态、错误码和重试次数。
3. 对文件工具记录规范化路径、动作类型、文件大小、哈希、是否成功和关联产物；页面按权限隐藏敏感路径。
4. 对桌面工具记录目标应用、窗口标识、操作阶段、UIA 验证结果、提交验证结果和截图证据。
5. 对命令执行记录命令类型、工作目录、退出码和截断后的输出；Secret、Token 和环境变量必须自动脱敏。
6. 工具返回“成功”与 Agent 最终文本声称“成功”不一致时，系统应标记结果不一致告警。
7. 不允许普通管理员在后台直接构造任意 shell 命令绕过 Agent 权限策略。

### 8.10 高风险操作确认与审批

1. 风险级别至少分为低、中、高、禁止。
2. 删除或覆盖重要数据、安装软件、修改系统安全设置、关机重启、使用凭据和向外部人员发送内容默认属于高风险。
3. 高风险任务进入“等待确认”，向原微信会话发送清晰的动作、影响范围和确认方式。
4. 确认应绑定 task ID、动作摘要和有效期，不能用一条模糊“确认”授权其他任务。
5. 超时未确认自动取消；拒绝和超时均需记录。
6. 后续可配置必须由后台管理员二次审批的策略。

### 8.11 电脑节点与服务管理

1. 展示节点名称、主机标识、操作系统、在线状态、最后心跳、当前登录用户、屏幕锁定状态和 Agent 版本。
2. 展示节点能力：命令行、文件、Desktop MCP、UIA、截图、可用应用和限制条件。
3. 展示 Bridge、Harness Runtime、Desktop Worker、后台 API 和可选旧 Java 服务的 PID、启动时间、状态、CPU/内存摘要和最近错误。
4. 支持启动、停止和重启受管子服务；操作必须经过权限校验和审计。
5. 后台 API 不应直接负责终止自身。实际进程操作由独立 Local Supervisor 执行。
6. 支持健康检查和“进程存在但功能不可用”的深度检查，例如微信认证、Harness 初始化和 Desktop MCP 握手。
7. 节点离线时任务不得被错误标记为成功，应进入失败、等待或重新路由状态。

### 8.12 文件与交付管理

1. 记录任务产生、读取、压缩、截图和发送的文件元数据，不默认复制保存所有用户文件内容。
2. 展示文件名、类型、大小、哈希、来源、创建时间、关联任务、保留期限和安全扫描状态。
3. 展示企业微信上传和发送状态、media ID 的脱敏标识、错误、重试次数和过期时间。
4. 支持在权限允许时重新发送已经存在且未过期/未删除的文件。
5. 文件超过企业微信限制、为空、路径不存在或为目录时给出明确失败原因。
6. 目录必须先压缩成文件再发送，并在记录中关联原目录摘要和压缩产物。
7. 默认限制可发送目录和文件类型；涉及凭据、密钥和系统敏感文件时阻止发送并告警。
8. 清理文件时只清理系统管理的产物目录，不得根据数据库中的任意路径递归删除用户目录。

### 8.13 Agent、模型与工具设置

1. 管理 Harness 启用状态、Provider、Model、最大 token、请求超时、工作目录和会话目录。
2. 管理系统提示词时支持草稿、校验、发布、版本对比和回滚。
3. 只保存公开配置和提示词，不在普通页面展示 API Key。
4. API Key 和 Secret 使用加密存储或 Windows 凭据能力，修改时采用“写入新值”方式。
5. 管理 Desktop MCP、文件、命令行等工具的启停和用户授权范围。
6. 工具策略支持按微信连接、用户、角色、节点和风险级别组合生效。
7. 配置发布前执行静态校验；影响运行中的变更需提示是否等待任务完成。
8. 每个任务必须记录实际使用的配置版本，便于复现和审计。

### 8.14 实时日志与诊断

1. 将 Bridge、Harness、Desktop Worker、Local Supervisor、后台 API 和旧 Java 日志统一展示。
2. 支持按时间、级别、服务、节点、微信连接、用户、session ID、task ID、tool call ID 和关键词筛选。
3. 支持实时流式查看、暂停滚动、复制单条、下载筛选结果和跳转到关联任务。
4. 日志至少包含结构化时间、级别、服务、事件名、trace ID 和消息；保留原文本作为兼容字段。
5. 自动脱敏 Bot Secret、API Key、Authorization、Cookie、Token 和疑似凭据。
6. 日志文件轮转，限制单文件大小和保留天数，避免磁盘被占满。
7. “查看实时日志”失败时不影响机器人主链路。
8. 保留原有文本日志作为应急兜底，但后台检索应主要依赖结构化事件。

### 8.15 告警与通知

1. 连接连续认证失败或长时间断线时产生告警。
2. 任务超时、失败率异常、会话碰撞、Harness Runtime 崩溃和 Desktop Worker 无响应时产生告警。
3. 文件连续发送失败、磁盘空间不足和日志写入失败时产生告警。
4. 告警支持待处理、处理中、已解决和已忽略状态，并记录处理人和备注。
5. 第一阶段在后台展示；后续可发送到企业微信指定管理员。

### 8.16 审计、导出与数据保留

1. 所有登录、权限、凭据轮换、配置发布、连接切换、任务控制和数据导出操作必须审计。
2. 审计记录不可通过普通业务接口修改；删除遵循单独的数据治理流程。
3. 支持按时间、对象和操作者导出 CSV/JSON；对话正文与本地路径按权限脱敏。
4. 可分别配置消息、任务、工具详情、日志、文件元数据和产物的保留期限。
5. 清理任务必须先生成待清理范围，记录执行结果，并支持对重要任务设置保留锁。
6. 支持数据库备份、配置备份和恢复演练；密钥材料不得直接进入普通备份。

## 9. 关键业务流程

### 9.1 消息到任务的完整链路

```text
微信连接收到消息
  -> 校验连接与用户权限
  -> message_id 幂等去重
  -> 保存入站消息
  -> 创建或定位逻辑会话与 Agent 会话代次
  -> 创建 Agent 任务和 trace ID
  -> Harness 执行并持续写入结构化事件
  -> 工具调用/电脑操作/文件产物关联任务
  -> 企业微信发送进度、最终回复和文件
  -> 保存每次发送结果
  -> 汇总任务最终状态
```

任何阶段失败都必须保存明确的失败阶段，避免只留下“任务处理失败”。

### 9.2 切换企业微信机器人

```text
创建或编辑候选连接
  -> 独立认证测试
  -> 发布前校验
  -> 检查运行任务
  -> 新 Worker 建立连接并认证
  -> 标记新连接为主连接
  -> 旧连接停止接收新任务并安全下线
  -> 记录发布结果
```

如果新连接认证失败，旧连接保持不变，候选配置标记为发布失败。

### 9.3 停止任务与结束会话

- **停止任务**：终止当前 Runtime/工具执行，将任务标记为已取消或停止失败；默认轮换 Agent 会话，避免被中断上下文污染后续任务。
- **结束会话**：无论是否有运行任务，都关闭当前 Agent 会话代次并创建新代次；历史记录继续可查。
- 两者可以组合，但后台按钮和审计事件必须分开。

### 9.4 高风险动作确认

```text
Agent 识别高风险动作
  -> 创建审批单并暂停任务
  -> 向原微信会话发送影响范围与确认口令
  -> 用户在有效期内确认/拒绝
  -> 重新校验确认人与 task ID
  -> 执行或取消
  -> 保存结果与证据
```

### 9.5 文件发送

```text
Agent 确认本地文件
  -> Bridge 校验真实文件、大小和策略
  -> 创建文件产物与交付记录
  -> 上传企业微信临时媒体
  -> 发送到原会话
  -> 保存成功或失败状态
  -> 将交付结果汇总到任务
```

## 10. 状态模型

### 10.1 任务状态

```text
RECEIVED -> QUEUED -> RUNNING
RUNNING -> WAITING_CONFIRMATION -> RUNNING
RUNNING -> SUCCEEDED | PARTIAL_SUCCEEDED | FAILED | TIMED_OUT | CANCELLED
QUEUED/RUNNING -> INTERRUPTED（进程异常退出）
```

系统启动恢复时，数据库里仍为 `RUNNING` 但没有对应存活 Runtime 的任务必须转为 `INTERRUPTED`，不能继续显示“处理中”。

### 10.2 微信连接状态

```text
DRAFT -> VALIDATING -> READY -> CONNECTING -> ONLINE
CONNECTING/ONLINE -> DEGRADED -> RECONNECTING -> ONLINE
任意运行状态 -> DISABLED
认证失败 -> FAILED
```

### 10.3 文件交付状态

```text
PENDING -> VALIDATING -> UPLOADING -> SENDING -> SENT
VALIDATING/UPLOADING/SENDING -> FAILED
FAILED -> RETRYING -> SENT | FAILED
```

## 11. 数据管理范围与建议数据模型

### 11.1 身份与权限数据

- `admin_user`：后台账号、状态、密码哈希、最后登录时间。
- `role`、`permission`、`user_role`：角色权限关系。
- `wecom_identity`：企业微信 UserID、连接归属、授权状态和策略。
- `login_session`：后台登录会话、过期时间和撤销状态。

### 11.2 微信连接数据

- `channel_connection`：连接名称、类型、Bot ID、Secret 引用、状态和路由策略。
- `connection_revision`：配置版本、发布人与发布时间。
- `connection_runtime`：Worker 实例、认证状态、最后心跳和错误。

### 11.3 对话与任务数据

- `conversation`：逻辑会话、连接、用户、状态和最近活跃时间。
- `agent_session`：代数、Harness session 标识、创建原因、状态和配置版本。
- `message`：消息 ID、方向、类型、正文、状态、时间和关联任务。
- `agent_task`：请求、状态、结果、耗时、trace ID 和失败阶段。
- `task_step`：公开步骤摘要、顺序、状态和耗时。
- `tool_call`：工具名、输入/输出摘要、状态、错误和关联步骤。
- `approval_request`：风险动作、确认人、有效期和结果。

### 11.4 节点、文件与运维数据

- `computer_node`：主机、版本、能力、在线和最后心跳。
- `service_instance`：服务类型、PID、状态、启动时间和健康结果。
- `file_artifact`：文件元数据、哈希、来源、保留策略和关联任务。
- `file_delivery`：上传、发送、重试和错误信息。
- `log_event`：结构化日志、服务、级别、trace ID 和脱敏内容。
- `alert`：告警类型、级别、状态、处理人与关联对象。
- `audit_event`：操作者、动作、对象、变更摘要和结果。
- `config_revision`：Agent、模型、工具和安全策略版本。

### 11.5 数据关联原则

1. 所有消息、任务、步骤、工具调用、文件和日志优先使用 `trace_id` 贯通。
2. 原始企业微信 message ID 保持唯一，数据库唯一约束用于防止重试消息重复执行。
3. 历史对象引用具体配置版本，不只引用“当前配置”。
4. 对话、任务、审计默认软删除或归档；清理按数据保留策略异步执行。
5. 大文件和截图正文不直接存入关系数据库，数据库只保存受控文件引用和元数据。

## 12. 管理接口与实时事件需求

### 12.1 管理 API 领域

- `/auth`：登录、退出、当前账号和密码修改。
- `/dashboard`：总览指标和异常摘要。
- `/connections`：微信连接、验证、发布、切换、启停和运行状态。
- `/wecom-users`：用户、授权和策略。
- `/conversations`、`/messages`、`/agent-sessions`：对话检索和会话控制。
- `/tasks`、`/tool-calls`、`/approvals`：任务查看、停止、重试和审批。
- `/nodes`、`/services`：节点健康和受管服务控制。
- `/artifacts`、`/deliveries`：文件记录和重新发送。
- `/configs`：配置草稿、校验、发布、对比和回滚。
- `/logs`、`/alerts`、`/audit-events`：日志、告警和审计。

### 12.2 实时事件

后台至少需要订阅以下事件：连接状态变化、任务状态变化、任务进度、工具调用开始/结束、文件发送状态、服务健康变化、新日志和新告警。

第一阶段可使用 Server-Sent Events 提供单向实时流；需要复杂双向控制时再使用 WebSocket。所有控制操作仍通过带权限和审计的普通 API 提交。

### 12.3 幂等与并发

1. 消息接收以企业微信 message ID 幂等。
2. 停止、重试、切换连接和发布配置需要幂等键，重复点击不能产生多个相同动作。
3. 更新配置采用版本号或 ETag，防止两个管理员相互覆盖。
4. 同一逻辑会话默认串行执行普通任务，控制命令可绕过任务锁执行。

## 13. 非功能需求

### 13.1 性能

- 普通列表查询在本机数据规模下 95% 响应时间小于 1 秒。
- 新消息和任务状态在后台中的可见延迟目标小于 2 秒。
- 实时日志正常情况下延迟小于 2 秒。
- 后台查询和日志查看不得明显阻塞微信消息处理链路。

### 13.2 稳定性

- Bridge、后台 API、连接 Worker 和 Supervisor 相互隔离，单个组件崩溃不应造成全部状态不可恢复。
- 服务启动时执行运行中任务和连接状态校准。
- 日志、数据库或后台前端故障时，机器人主链路应尽可能继续运行并产生降级告警。
- 所有子进程需要明确的启动超时、停止超时和强制终止兜底。

### 13.3 可维护性

- 业务逻辑不写入 PowerShell UI 事件处理器。
- Python Bridge、管理 API、持久化、微信适配器、Agent 适配器和节点控制使用清晰模块边界。
- 数据库迁移必须版本化，配置格式必须可校验。
- 关键状态机和权限策略具备单元测试与端到端测试。

### 13.4 可观测性

- 每个请求贯穿 `message_id`、`task_id`、`trace_id` 和 `agent_session_id`。
- 关键事件采用结构化日志和稳定事件名称。
- 错误信息同时包含用户可读说明、内部错误码和可定位日志。

### 13.5 兼容性

- 支持当前 Windows 运行环境和企业微信智能机器人 SDK。
- 保留现有 `.env` 导入能力用于第一次迁移，但迁移后以配置存储为准。
- 保留文本日志和桌面应急控制入口，便于后台自身故障时排查。

## 14. 安全与隐私要求

1. 后台默认仅绑定 `127.0.0.1`，不得默认暴露到公网。
2. Bot Secret、DeepSeek API Key 等凭据必须加密保存，推荐使用 Windows DPAPI/凭据管理器保护本机密钥。
3. 页面和接口只返回凭据是否已配置、最后轮换时间和掩码，不返回原值。
4. 日志和工具输入输出统一经过脱敏器。
5. 文件访问采用允许目录、禁止类型、大小限制和敏感文件规则。
6. 高风险动作必须二次确认，禁止通过后台“万能命令框”绕过。
7. 导出和查看敏感对话需要单独权限并记录审计。
8. 若未来开放远程后台，必须使用 HTTPS、强认证、网络访问控制和会话超时；优先通过 VPN/零信任网络访问而非直接映射端口。
9. UIA 和桌面操作不得突破锁屏、UAC 安全桌面或验证码。

## 15. 推荐技术与部署架构

### 15.1 总体形态

推荐采用“模块化单体管理后台 + 独立本机节点控制器 + 独立执行进程”，而不是一开始拆成大量微服务：

```text
桌面快捷方式 / 托盘入口
  -> Local Supervisor
       -> 启停与健康检查 Admin API、Bridge、连接 Worker
       -> 提供严格受限的本机进程控制接口

浏览器管理后台
  -> Admin API
       -> 关系数据库
       -> 结构化事件/审计存储
       -> Supervisor 控制接口

企业微信 Connection Worker
  -> Message Processor
  -> Unified Agent / Harness
  -> Desktop MCP Worker
  -> 文件交付

Bridge、Harness、工具与 Supervisor
  -> 结构化事件和日志
  -> Admin API/事件存储
```

### 15.2 后端建议

- 管理 API 推荐使用 **FastAPI**，作为独立入口和进程，而不是把 HTTP 服务塞进现有 `bridge.py` 或长连接主循环。
- 原因是主执行链已经在 Python 中，FastAPI 可以直接复用领域类型、异步任务状态和持久化模块，减少 Java/Python 两套模型同步。
- 现有 Spring Boot 保持兼容服务，不建议作为新后台核心，除非团队明确决定长期以 Java 为主并迁移整个 Agent 控制面。
- 建议使用 SQLAlchemy 2.x 和 Alembic 管理数据库与迁移。
- 第一阶段单机可以使用 SQLite WAL 快速落地；正式多管理员、多连接或多节点部署推荐 PostgreSQL。数据访问层应避免依赖 SQLite 特有行为。
- 实时日志和任务进度第一阶段使用 SSE；不必为了单机后台先引入 Redis。后续多节点时再增加可靠消息总线。

### 15.3 前端建议

- 推荐 Vue 3 + TypeScript + Vite + Pinia + 成熟的管理后台组件库。
- 页面模块按领域拆分，不把所有日志和业务对象放进一个大页面。
- 前端只通过 Admin API 操作，不直接读写 `.env`、JSON 会话文件或日志文件。

### 15.4 本机节点控制器建议

- 从现有 PowerShell 启停逻辑中提炼进程发现、PID 校验、启动、停止、日志路径和健康检查规则。
- 最终由常驻 Supervisor 管理子进程，PowerShell 只负责启动 Supervisor、打开后台页面和提供故障兜底。
- Supervisor 必须独立于 Admin API，否则在后台点击“停止全部”时会把执行控制者自身一起终止，无法返回可靠结果。
- Admin API 与数据库可以后台运行，但需要操作桌面的 Supervisor、Bridge 和 Desktop Worker 应位于当前登录用户的交互式会话，可使用登录启动项或计划任务拉起。
- Supervisor 应记录自己创建的进程句柄、完整命令行、工作目录和实例 ID，不能只根据端口或进程名猜测归属。现有启动器在状态文件丢失后按 8080 端口接管 Java 进程的逻辑不应直接沿用，以免终止其他 Java 服务。
- 正常停止顺序应为：停止接收新任务、取消/等待当前任务、关闭 Harness 与 Desktop Worker、等待退出，最后才使用进程树强制终止。“紧急强停”作为独立操作保留。

## 16. 桌面快捷启动器的整合方案

### 16.1 可以复用的能力

- 项目根目录和运行目录定位。
- Bridge、旧 Java 的启动、PID 与启动时间校验。
- 子进程树停止。
- 日志文件路径和尾部实时读取。
- 重复启动检测。
- 桌面快捷方式和项目图标。

### 16.2 不应继续放入启动器的功能

- 对话记录、任务列表、用户权限和微信连接配置页面。
- 数据库查询、配置版本、发布回滚和审批。
- 业务对象检索、审计导出和文件记录管理。
- 明文 Secret/API Key 编辑。
- 任意命令执行入口。

### 16.3 最终用户体验

1. 用户双击“企业微信电脑助手”。
2. 启动器检查并启动 Local Supervisor。
3. Supervisor 启动 Admin API 和机器人运行服务。
4. 默认浏览器打开本机后台，例如 `http://127.0.0.1:<管理端口>`。
5. 桌面小窗口或托盘只显示总状态，并提供“打开后台”“启动/停止机器人”“高级日志”“退出控制器”。
6. 详细对话、任务、工具调用、微信切换和实时日志全部在 Web 后台完成。
7. 后台故障时，用户仍可用启动器高级日志页停止进程或打开日志目录。

因此，答案不是“完全抛弃现有启动器”，也不是“直接在 WinForms 窗口里继续加页面”，而是复用它的本机控制能力，逐步将业务管理能力迁移到独立 Web 后台。

## 17. 分阶段实施计划

### 阶段 0：事件与持久化基础

- 定义 `task_id`、`trace_id`、状态枚举和结构化事件协议。
- 引入数据库迁移和 Repository 层。
- 在不改变现有微信行为的前提下，落库消息、任务、工具调用、文件发送和连接状态。
- 增加日志脱敏与轮转。
- 接入 Harness `on_notification` 回调，实时归一化 `session.event`、`session.status`、工具和子 Agent 事件。
- 将消息幂等从内存检测升级为数据库唯一约束，并设计 Bridge 重启后的运行任务对账。

### 阶段 1：可用的本机管理后台

- 完成登录、仪表盘、对话、任务详情、工具调用、文件发送、实时日志和服务状态。
- 完成停止任务、结束会话、失败任务重试和文件重新发送。
- 单超级管理员、单电脑节点、单主微信连接。
- 桌面快捷方式启动后台并打开浏览器。

### 阶段 2：微信与 Agent 配置管理

- 多套微信连接配置、连接测试、原子切换和回滚。
- 用户授权、工具权限、风险策略和允许目录。
- Agent/模型/提示词配置版本、发布和回滚。
- 凭据加密存储并从 `.env` 一次性迁移。

### 阶段 3：权限、审批与运维增强

- 多管理员 RBAC、敏感数据权限和审计导出。
- 高风险操作审批和后台告警。
- 数据保留、备份恢复和系统自检。
- Local Supervisor 常驻化和托盘体验完善。

### 阶段 4：多连接与多节点

- 多机器人同时在线、独立 Worker 隔离和路由。
- 多电脑节点、节点升级、任务调度和远程健康管理。
- PostgreSQL、可靠事件总线和更完整的可观测性。

## 18. 第一阶段验收标准

1. 用户发送一条企业微信任务后，后台在 2 秒目标时间内出现对应消息和任务。
2. 任务详情能按时间线显示 Agent 开始、工具调用、操作结果、截图/文件和最终回复。
3. 豆包问答任务能明确展示打开应用、写入验证、提交验证、回答检测和截图各阶段结果。
4. 任一失败任务都能展示内部错误码、失败阶段和已关联的筛选日志，不只显示 `UNKNOWN`。
5. 点击停止任务后，后台显示停止请求和最终结果；下一条用户消息不会继承被中断的脏会话。
6. 执行 `end` 后，旧对话记录保留，新任务使用新的 Agent 会话代数。
7. 文件发送显示校验、上传、发送和失败原因，支持安全地重新发送现有产物。
8. 可保存至少两套企业微信连接配置；候选连接认证失败时，当前在线连接不受影响。
9. 所有 Bot Secret 和 API Key 在页面、接口、日志和导出中均不可见明文。
10. 桌面快捷方式能启动机器人和管理后台、打开浏览器，并保留停止进程和高级日志兜底。
11. Bridge 或后台重启后，历史数据可查，遗留运行任务被自动标记为异常中断。
12. 单元测试覆盖任务状态机、消息幂等、权限校验、连接切换、配置版本、敏感信息脱敏和文件路径安全；关键链路具备端到端测试。

## 19. 需求优先级

### P0：没有则无法形成后台闭环

- 数据库与结构化事件。
- 登录与基本安全。
- 对话、消息、任务、工具调用和文件交付记录。
- 任务状态恢复、停止任务和结束会话。
- 服务状态、实时日志、错误码和 trace ID。
- 单主微信连接及配置查看。
- 桌面入口启动后台。

### P1：形成可运营、可配置系统

- 多微信配置、连接测试、安全切换和回滚。
- 用户授权和工具权限。
- Agent 配置版本、发布和回滚。
- 凭据加密存储。
- 告警、数据保留和备份。

### P2：面向多人和规模化

- 多角色 RBAC、审批流和敏感数据分级。
- 多机器人同时在线。
- 多电脑节点、任务路由和远程升级。
- 统计分析、成本、质量评估和外部告警集成。

## 20. 默认决策与待确认项

若未另行指定，后续技术设计按以下默认决策推进：

1. 第一阶段只正式支持企业微信智能机器人，通道模型为以后扩展预留。
2. 使用独立 FastAPI 管理 API，不把后台 HTTP 逻辑写进 Bridge 消息循环。
3. 使用 Vue 3 + TypeScript 构建管理前端。
4. 第一阶段单机使用 SQLite WAL + Alembic，数据层保持可迁移 PostgreSQL。
5. 同一时刻一套主微信连接在线，先实现安全切换，再扩展多连接并行。
6. 当前 PowerShell 窗口保留为本机启动和应急诊断入口，业务后台使用浏览器。
7. 不保存模型私有思维链，只保存公开计划摘要、工具调用、结果和证据。
8. 管理后台默认仅本机访问；远程访问在完成 HTTPS 和强认证后另行开启。
